# WEB-SPEC — the web app's contract

The laws of `web/` are its tests, and a test's name states its law:
`web/test/*.test.ts` (node, over the seeded generator `web/test/gen.ts`, which
prints the failing seed; `scripts/web-test.sh`), `web/e2e/` (a real browser,
`scripts/web-e2e.sh`), and the Rust tests of what the tab draws and reads
(`app/viewtree/tests`, `app/pages/tests`, `app/core/tests`, `app/cli/tests`).
This document holds what no test holds: where to start reading, the three
doors, the laws no test checks, and the vectors. A new law is a new test, not
a sentence here.

## 1. Where to start

- **The shell**: `app.App` (`web/src/app/app.ts`), one pure `app.step` over
  the closed `app.Event`; `chrome.of` (`web/src/shell/chrome.ts`) is what the
  shell draws around the page.
- **The address**: `Route` (`web/src/shell/route.ts`), resolved against the
  width into a `Screen` (`web/src/shell/layout.ts`); `pages.table`
  (`web/src/pages/table.ts`) mounts one page per screen.
- **A page drawn in TypeScript**: a `frame.Page` (`web/src/view/frame.ts`) over
  one `source.Source` (`web/src/algebra/source.ts`). What it asks the box is
  `asked` (`web/src/app/asked.ts`); it loads nothing itself.
- **A page drawn in Rust**: a `viewtree::Program` (`app/pages/`), painted by
  `web/src/painter/painter.ts` and run by `web/src/pages/program.ts`.
- **What the tab holds**: replicas of the box's objects
  (`web/src/prodrome/replica.ts`, and the stores' in `app/core/src/replica/`),
  read and moved by the core in its worker (`web/src/prodrome/questions.ts`).
- **The tab's own state**: registers, each declared once with its tier in
  `web/src/app/registers.ts`.
- **The wire**: types and decoders generated into `web/src/wire/generated/`
  from `app/core/src/wire.rs` by `scripts/wire.sh`; `web/src/wire/api.ts`
  names each route once.

## 2. The doors

Untyped data enters by three doors, and `scripts/web-static.sh` refuses a
fourth:

1. **`web/src/view/dom.ts`**: `el` and text nodes. No source parses markup
   from a string.
2. **`web/src/rich.ts`**: the one `innerHTML`, for Typst's HTML alone. It
   takes HTML the box compiled, or a view or a preview the tab compiled with
   typst-wasm in the restricted project (no `html`, no `plugin`), and only
   after the box's tripwire (`suzatary_core::tripwire`) refused any script,
   handler or executable URL. The page never sends text to be rendered: it
   asks for an answer block by its sha, a reading page by todo id and a
   briefing by date.
3. **The generated decoders** (`web/src/wire/generated/payload.ts`), through
   `http.get`, `http.act` or `d.json`: the only way wire bytes, and the wasm's
   answers, become a typed value.

## 3. The laws no test checks

- No refusal of the add sheet is drawn under the phone's tab bar.
- An `Owner` register (a draft to the secretary) never enters a store the box
  pushes to git.

A DOM is checked in a real browser or over a small fake DOM written in the
test, never jsdom.

## 4. The vectors

The Rust writes them and the TypeScript must agree with them. A disagreement
is a finding, never a vector to refresh.

- **The wire**: regenerated by `scripts/wire.sh`, never edited.
- **Fulfillment**: `web/test/wasm.test.ts` drives the core's wasm under node
  against the Prodrome's frozen conformance vectors and this chain.
- **`app/core/tests/web/`**: read by both sides. A file a Rust test writes
  (most, by `app/core/tests/web_vectors.rs`) is written only under
  `SUZATARY_WRITE_VECTORS=1`, in the same change as the Rust that moves it;
  otherwise that test recomputes it and compares the committed bytes.
  `closed-world.json` is written by hand.
